- **`classes` vs `courses` vs `class_subjects`:** three distinct concepts (cohort / global catalogue / cohort-subject) with confusingly similar names â€” not duplicated responsibilities, but the naming invites bugs. See DATABASE_NAMING_AUDIT.
- **`class_members` vs `class_admins`:** membership vs admin role as separate junction tables; admin is NOT a member-role value (VERIFIED separate tables + separate RLS).
- **`discussion_sessions` dual role:** scheduling and attendance share one table â€” the largest domain overlap.
- **`assignments` triple scope** (`course_id`, `class_id`, `subject_id`): ownership precedence is app/RLS-defined, not DB-defined.
