# RLS & Security Audit — 83 public policies + 18 storage policies (Phase 3)

Evidence: `SELECT schemaname, tablename, policyname, cmd, roles, qual, with_check FROM pg_policies WHERE schemaname='public' ORDER BY tablename, policyname;` — full result captured 2026-11-04. All 52 public tables have `relrowsecurity=true`. No policy was modified.

## Authorization kernel

- `is_class_member(p_class_id)` — verified definition: `exists (select 1 from public.class_members m where m.class_id=p_class_id and m.user_id=(select auth.uid()))`, `STABLE SECURITY DEFINER SET search_path TO ''`. Correctly binds to caller, not to a client-supplied user id.
- `is_class_admin`, `is_platform_admin`, `can_manage_class` (= `is_platform_admin() or is_class_admin(p_class_id)`), `can_view_leave_request`, `can_view_session` — definitions spot-verified, same `SET search_path` pattern (one exception below).
- `can_view_session`: allows `visibility='public'`, platform admin, class member/admin, or RSVP holder. Public sessions are readable by any authenticated user — intentional, note for multi-tenant (today's "public" is global).

## Notable exceptions / risks

1. **P1 — `class_course_schedules` member-write.** Any class member can insert/update/delete a shared schedule (`20261029003400_class_course_schedule.sql` pattern). If that is not intended, tighten to `is_class_admin`. **Do not change in Phase 3.**
2. **P2 — `class_subjects` world-readable when active.** Same for `classes` active rows and `assignments_public_read`. Fine as public catalogue; becomes cross-university leak once multiple universities exist. Multi-tenant design must scope these.
3. **P2 — `can_view_leave_request` uses `SET search_path TO 'public','pg_temp'`** (not `''`). Works, but `pg_temp` in path means a temp object could shadow. Low risk; standardize to `''` in a future migration with per-function diff tests.
4. **No policy uses `USING (true)` except `courses_public_read` and `profiles_public_read`** — both intentional public data. No evidence of open-redirect or service-role leakage in policies (policies don't carry secrets).
5. **Storage policies (18, see STORAGE_SECURITY_AUDIT.md):** read/write separated; write gated by folder=user-id or class-admin. `class-media` read is the only public-read bucket with class content.

## Tenant implications

None of the 83 policies reference a tenant. Adding `university_id` requires touching every policy (listed above) — HIGH effort, hence Phase 4 gate. Until then, cross-class isolation rests entirely on `is_class_member` being called with the correct `class_id`; helpers verified to bind `auth.uid()` server-side.
