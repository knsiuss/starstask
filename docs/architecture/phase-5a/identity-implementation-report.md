## 2. What was decided (summary — detail in decision-register.md)

- Build **additive** `universities` + `university_memberships` tables only (D-01…D-10).
- Membership naming: `university_memberships` (per the 5A brief) rather than the
  Phase 4C name `student_identities`. Rationale: Phase 4C's `student_identities`
  carries NOT NULL `entry_year`/`full_name_snapshot` plus an FK into
  `academic_units` (ADR-003, APPROVED but not yet built). A `student_identities`
  table cannot satisfy its own NOT NULL constraints today; `university_memberships`
  is the minimal persona bridge that satisfies ADR-001 + ADR-004 (nullable
  `entry_year`, documented as immutable-post-activation in the target design).
  Renaming/expanding into `student_identities` is scheduled for Phase 5B.
- **Keep** `profiles.university` and `profiles.nim` untouched; no default tenant
  row; no backfill of any kind.
- **No** `university_id` added to any unrelated table (no tenant boundary is yet
  enforced anywhere — this is greenfield, verified in evidence-closure §6).
- **No** new SECURITY DEFINER functions. RLS is read-only for clients; platform
  writes go through service_role, the same convention as `platform_admins`.
- `universities.created_by → profiles(id) ON DELETE SET NULL` — the only direct
  FK to `profiles` in the repo (all pre-existing FKs use `auth.users`).

## 3. What was migrated

**`supabase/migrations/20261111000000_universities_and_memberships.sql`** (new file,
numbered after the WIP `20261110000000` to preserve ordering):

table `internal.pg_temp.temp_5a_literal`
| Object | Shape |
|---|---|
| `universities` | `id uuid PK default gen_random_uuid()`, `slug` unique (lowercase-hyphen regex), `code` (partial unique on `lower(btrim(code))`), `name` NOT NULL, `short_name`, `type`, `country`, `province`, `city`, `website`/`logo_url` (https-only), `timezone`, `locale`, `status CHECK (registered, pending, active, suspended, inactive) DEFAULT 'registered'`, `activated_at`, `deactivated_at`, `created_by → profiles SET NULL`, `created_at`, `updated_at` + `set_updated_at()` trigger, index on `status` |
| `university_memberships` | `id uuid PK`, `user_id → auth.users CASCADE`, `university_id → universities RESTRICT`, `student_id` (same format CHECK as NIM, partial unique on `(university_id, lower(btrim(student_id)))`), `role` (no CHECK — extensible per open Q4), `entry_year` (1950–2100), `status CHECK (pending, active, suspended, graduated)`, `UNIQUE(user_id, university_id)`, index `(university_id, status)`, `updated_at` trigger |
| RLS | Enabled on both. `universities`: REVOKE ALL from anon/authenticated, GRANT SELECT to authenticated, policy `universities_active_read USING (status = 'active')`. Memberships: REVOKE ALL, GRANT SELECT, policy `university_memberships_owner_read USING (user_id = (select auth.uid()))`. No INSERT/UPDATE/DELETE policies for any client role → NO self-grant. |

## 7. Rollback

Additive migration → rollback = remove one migration file + drop two tables in
reverse dependency order. **No destructive action was taken in Phase 5A.**
Local-only rollback:

```sql
-- local stack only (never remote):
drop table if exists public.university_memberships;  -- child first (FK RESTRICT)
drop table if exists public.universities;
-- then delete supabase/migrations/20261111000000_universities_and_memberships.sql
-- from the working copy; the 2 tables were never pushed remotely.
```

The generated-types revert is `git checkout -- apps/web/src/types/database.generated.ts apps/web/src/types/database.ts`.
`profiles.university`/`nim` were never touched, so the application needed no
rollback of any kind.
