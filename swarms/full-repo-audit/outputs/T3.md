## Detailed Findings

### [MEDIUM-1] `dm_sender_keys_owner_update` RLS policy omits participant validation in `WITH CHECK`

- **File + Line:** `supabase/migrations/20270126000000_dm_e2ee_v2_devices.sql#L121-L125` (contrast with `L100-L119`)
- **Evidence:**  
  `dm_sender_keys_owner_insert` (lines 100–119) verifies that both `owner_user_id` and `recipient_user_id` are active `dm_participants` (`left_at IS NULL`) in `conversation_id`. However, `dm_sender_keys_owner_update` (lines 121–125) only checks:
  ```sql
  USING (owner_user_id = (SELECT auth.uid ()))
  WITH CHECK (owner_user_id = (SELECT auth.uid ()));
  ```
- **Recommended Fix:** Add the same `dm_participants` `EXISTS` checks for `owner_user_id` and `recipient_user_id` to `dm_sender_keys_owner_update`'s `WITH CHECK`, or add a `BEFORE UPDATE` trigger enforcing immutability of `conversation_id`, `owner_user_id`, `owner_device_id`, `recipient_user_id`, `recipient_device_id`, and `key_id`.

### [MEDIUM-2] Unbounded strings and `students` array in `attendance-sync.ts`

- **File + Line:** `packages/contracts/src/attendance-sync.ts#L14-L34`
- **Evidence:**  
  - `syncStudentRecordSchema` (lines 14–18): `nim: z.string().nullable()` and `displayName: z.string()` have no `.max(...)` bounds.
  - `syncSessionPayloadSchema` (lines 22–28): `meetingId: z.string()`, `meetingTitle: z.string()`, `className: z.string()`, `expiresAt: z.string()`, and `students: z.array(syncStudentRecordSchema)` have no `.max(...)` bounds.
  - `attendanceSyncExchangeRequestSchema` (lines 32–34): `code: z.string().trim().min(10, "Sync code is invalid")` has no `.max(...)` bound.
- **Recommended Fix:** Add explicit `.max(...)` bounds to `nim`, `displayName`, `meetingId`, `meetingTitle`, `className`, `expiresAt`, `students` (e.g., `.max(500)`), and `code` (e.g., `.max(128)`).

### [MEDIUM-3] `gradeWeightsSchema` sum tolerance (`1e-6`) can pass Zod yet violate PostgreSQL `numeric(5, 2)` exact `= 100` constraint

- **File + Line:** `packages/contracts/src/academic.ts#L185-L193` vs `supabase/migrations/20270125010000_attendance_cutoff_and_grade_validation.sql#L7-L10`, `#L24-L26`
- **Evidence:**  
  `gradeWeightsSchema` validates `Math.abs(value.absensi + value.tugas + value.uts + value.uas - 100) < 1e-6`, whereas `course_grade_weights` stores each column as `numeric(5, 2)` and enforces `CHECK (absensi_weight + tugas_weight + uts_weight + uas_weight = 100)`. Inputs such as `33.333 + 33.333 + 33.334 + 0` pass Zod (`100`) but round in PostgreSQL to `33.33 + 33.33 + 33.33 + 0 = 99.99`, triggering a `23514` check constraint failure.
- **Recommended Fix:** Restrict weight inputs to at most 2 decimal places (or round to 2 decimal places before checking `sum === 100`) in `packages/contracts/src/academic.ts`.

### [LOW-1] `class_export_branding` lacks DB-level `CHECK` constraints matching `exportBrandingSchema`

- **File + Line:** `supabase/migrations/20270109000000_class_export_branding.sql#L4-L28`, `#L74-L97` vs `packages/contracts/src/export-branding.ts#L82-L138`
- **Evidence:**  
  `class_export_branding` grants `INSERT, UPDATE (...) TO authenticated` directly on the table, but defines no `CHECK` constraints on `passing_threshold` (`0..100`) or text column lengths (`university_name` <= 160, `document_title` <= 200, `footer_text` <= 300, etc.) that `exportBrandingSchema` enforces.
- **Recommended Fix:** Add `CHECK (passing_threshold >= 0 AND passing_threshold <= 100)` and `char_length(...)` constraints to `class_export_branding` in a follow-up migration.

### [LOW-2] `accept_class_invitation` and `accept_pending_invitation` increment `used_count` even on `ON CONFLICT DO NOTHING`

- **File + Line:** `supabase/migrations/20270127000000_export_and_join_fixes.sql#L152-L158`, `#L263-L269`
- **Evidence:**  
  Both RPCs run `INSERT INTO public.class_invitation_acceptances (invitation_id, user_id) ... ON CONFLICT DO NOTHING;` followed unconditionally by `UPDATE public.class_invitations SET used_count = used_count + 1 WHERE id = v_inv.id;`.
- **Recommended Fix:** Only increment `used_count` when the `INSERT INTO public.class_invitation_acceptances` actually inserts a new row (`IF FOUND THEN ...` using `RETURNING 1`).

### [LOW-3] `classJoinResultSchema` `candidates` array has `.min(1)` without `.max(...)`

- **File + Line:** `packages/contracts/src/profile.ts#L235`
- **Evidence:**  
  `candidates: z.array(joinCandidateSchema).min(1)` has no upper bound (used to parse `join_class_by_name` RPC output).
- **Recommended Fix:** Add a reasonable `.max(...)` cap (e.g., `.max(50)`) aligned with the RPC's `LIMIT`.

## Verified Clean / Passed Checks

1. **Migration Timestamps:** All 161 files in `supabase/migrations/` have unique timestamp prefixes (0 collisions).
2. **Table RLS Coverage:** All tables created across `supabase/migrations/` have `ENABLE ROW LEVEL SECURITY` (either directly or via `DO $$` loops in `20261113`–`20261116`). `public.profiles` uses `profiles_public_read` (`USING (TRUE)`) safely because column-level `GRANT SELECT (id, display_name, avatar_url)` restricts exposed columns (`20261029000300_rls.sql#L22-L41`).
3. **`SECURITY DEFINER` Hardening:** Every `SECURITY DEFINER` function across all 161 migrations defines `SET search_path` (`''` or `public, pg_temp`). Every active non-trigger `SECURITY DEFINER` function has `REVOKE ALL ... FROM PUBLIC` (`request_leave_revision` was dropped in `20261030090000_absence_cancellation.sql#L797`, and `prevent_assignment_status_escalation` is a trigger function).
4. **Function Overloads:** `grant_lecturer_membership_if_eligible` (`20270121000000_audit_logic_fixes.sql#L226`) and `create_class_invitation` (`20270122000000_course_scoped_invitations.sql#L12`) properly `DROP FUNCTION IF EXISTS` old signatures before creating updated ones.
5. **Views:** The 9 observability views are locked down with `security_invoker = TRUE` and `REVOKE ALL ... FROM anon, authenticated` (`20270103000000_security_view_lockdown.sql`), and `public.offering_bap_progress` (`20270125000000_schedule_collision_and_bap.sql#L112-L114`) uses `WITH (security_invoker = TRUE)`.
6. **`packages/shared/src/`:** `csv.ts` implements RFC 4180 escaping with formula-injection protection (`=`, `+`, `-`, `@`, `\t`, `\r`); `developer.ts` fails closed on invalid allowlist entries.
