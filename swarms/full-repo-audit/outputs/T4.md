## 2. Mobile Alignment Findings

### Finding 1 — Google Integration Disconnect Opens `GET` Browser Intent Against `POST`-Only Web Endpoints
- **Severity:** `HIGH`
- **File + Line:**
  - `apps/mobile/android/app/src/main/java/id/starstask/mobile/data/Integrations.kt:20-38`
  - `apps/web/src/app/api/integrations/google-calendar/disconnect/route.ts:18`
  - `apps/web/src/app/api/integrations/google-drive/disconnect/route.ts:12`
- **Evidence:**
  - `openIntegrationDisconnect` calls `openWebFlow(context, kind.disconnectPath)` which launches `Intent(Intent.ACTION_VIEW, android.net.Uri.parse(url))` to `/api/integrations/google-calendar/disconnect` and `/api/integrations/google-drive/disconnect` (a browser `GET` navigation).
  - Both web route handlers only export `POST()` with no `GET()` handler, so mobile users attempting to disconnect either integration receive `405 Method Not Allowed`.
- **Recommended Fix:**
  - Change `openIntegrationDisconnect` on mobile to issue an authenticated `POST` request with `Authorization: Bearer <accessToken>` (using the same `HttpURLConnection` pattern as `Calendar.kt:484`), instead of opening the disconnect API route in a browser `Intent`.

### Finding 2 — Mobile DM E2EE Only Implements v1 (`dm_keys`) and Lacks v2 Multi-Device Support (`dm_device_keys` / `dm_sender_keys`)
- **Severity:** `HIGH`
- **File + Line:**
  - `apps/mobile/android/app/src/main/java/id/starstask/mobile/data/DmKeys.kt:28-41`
  - `apps/mobile/android/app/src/main/java/id/starstask/mobile/data/DmChat.kt:112, 168, 199`
  - `apps/web/src/lib/crypto/e2ee-v2.ts:16-45`
  - `supabase/migrations/20270126000000_dm_e2ee_v2_devices.sql:4-47, 146-151`
- **Evidence:**
  - Web and database now support E2EE v2 (`v2:` / `v2g:` envelopes, `dm_device_keys`, `dm_sender_keys`, and `dm_messages.body` limit raised to 32,000 chars for multi-device envelopes), with endpoints `/api/dm/devices` and `/api/dm/conversations/[id]/sender-keys`.
  - Mobile `DmKeys.kt` and `DmChat.kt` only query `dm_keys` and use v1 ECDH P-256 `decryptDmMessage` / `encryptDmMessage`. Mobile has zero references to `dm_device_keys`, `dm_sender_keys`, or `v2:`/`v2g:` envelopes, so v2 messages sent from web devices cannot be decrypted on Android.
- **Recommended Fix:**
  - Implement device registration (`/api/dm/devices` / `dm_device_keys`), sender-key envelope handling (`dm_sender_keys`), and `v2:`/`v2g:` decryption in `DmKeys.kt` / `DmChat.kt`, or gate v2 sending until peer device capability is negotiated.

### Finding 6 — `Calendar.kt` Drops `eventId` Because `apiSuccess` Wraps Response in `{ data }`
- **Severity:** `LOW`
- **File + Line:**
  - `apps/mobile/android/app/src/main/java/id/starstask/mobile/data/Calendar.kt:502-505`
  - `apps/web/src/app/api/sessions/[id]/calendar-sync/route.ts:118`
  - `apps/web/src/lib/api/responses.ts:17-25`
- **Evidence:**
  - `calendar-sync/route.ts:118` returns `apiSuccess(result)`, which wraps `result` as `{ "data": { ... } }` (`responses.ts:18-19`).
  - `Calendar.kt:504` reads `Json.parseToJsonElement(body).jsonObject["eventId"]?.jsonPrimitive?.content` at the root object rather than under `"data"`, so `eventId` is always `null` on mobile.
- **Recommended Fix:**
  - Read `jsonObject["data"]?.jsonObject?.get("eventId")?.jsonPrimitive?.content` (with fallback to root) in `Calendar.kt:504`.
