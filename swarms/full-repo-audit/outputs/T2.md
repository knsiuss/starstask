## Findings

### [HIGH] 1. `/developer/observability` placed in `(workspace)` instead of `(console)/developer`, bypassing `DeveloperLayout` allowlist

- **File + Line:** `apps/web/src/app/(workspace)/developer/observability/page.tsx:14-16, 38-75` and `apps/web/src/components/developer/developer-nav.tsx:27-37`
- **Evidence:**
  - `ObservabilityPage` lives under `(workspace)/developer/observability/page.tsx` instead of `(console)/developer/observability/page.tsx`. As a result, it renders inside `WorkspaceLayout` (student sidebar/topbar) and bypasses `DeveloperLayout`'s `requireDeveloperPageAccess("/developer")` email allowlist, only checking `requirePlatformAdmin("/developer/observability")` (line 15).
  - `/developer/observability` is missing from `DEVELOPER_ITEMS` in `developer-nav.tsx:27-37`.
  - Line 16 declares `const supabase = await createSupabaseServerClient();` which is never used.
  - Lines 39, 40, 41, 49, 50, 51, 59 contain 7 `any` usages (`as any`, `(r: any)`), violating `AGENTS.md` §4.1.
  - Lines 38, 48, 58, 70 place `<p>`/`<ul>` directly inside `<Card>` without `<CardContent>`.
- **Recommended Fix:** Move `page.tsx` to `apps/web/src/app/(console)/developer/observability/page.tsx`, enforce `requireDeveloperPageAccess("/developer/observability")`, add `/developer/observability` to `DEVELOPER_ITEMS` in `developer-nav.tsx`, remove the unused `supabase` variable, type the observability view rows explicitly, and wrap card bodies in `<CardContent>`.

### [HIGH] 2. `CallButton` & `StoryRow` have unhandled errors, broken video preview, `as any` casts, and emoji UI icons

- **File + Line:** `apps/web/src/components/messages/call-button.tsx:16-66` and `apps/web/src/components/messages/story-row.tsx:25, 55, 66, 104`
- **Evidence:**
  - `call-button.tsx:16-41`: `startCall` lacks `try/catch` around `navigator.mediaDevices.getUserMedia(...)`, `pc.createOffer()`, and `supabase.from("dm_calls" as any).insert(...)`. Media permission denial or network failure causes an unhandled promise rejection with no UI error state.
  - `call-button.tsx:60-66`: `<video autoPlay muted className="h-10 w-10 rounded" />` never binds `localStream` to `videoRef.current.srcObject`.
  - `call-button.tsx:30` and `story-row.tsx:25, 55`: use `"dm_calls" as any` and `"dm_stories" as any` (`AGENTS.md` §4.1).
  - `call-button.tsx:50, 57` and `story-row.tsx:104`: render raw emojis (`📞`, `📹`, `👤`) as UI icons, violating the project's no-emoji UI rule.
  - `story-row.tsx:66`: calls `window.location.reload()` after upload instead of updating state or calling `router.refresh()`.
- **Recommended Fix:** Add `dm_calls` and `dm_stories` to generated Supabase `Database` types, wrap `startCall` in `try/catch` with visible error feedback, attach `localStream` to a `<video ref={...}>` via `useEffect`, replace `📞`/`📹`/`👤` with Lucide icons (`Phone`, `Video`, `User`), and update `stories` state in-place after upload.

### [MEDIUM] 3. `chat-pane.tsx` silently swallows mutation failures and misuses `error` state for success copy

- **File + Line:** `apps/web/src/components/messages/chat-pane.tsx:756, 762, 814, 821, 1190-1211, 1263, 1270-1283`
- **Evidence:**
  - `react` (lines 1190-1211) and `togglePin` (lines 1270-1283) attach `.catch(() => {})` to `fetch(...)` and do not check `response.ok`, then unconditionally update `setMessages(...)`. Failed requests leave the UI permanently out of sync with the server with no error feedback.
  - `copyMessage` (line 1263) calls `setError("Copied to clipboard")`, displaying a success confirmation inside the error state/alert.
- **Recommended Fix:** Check `response.ok` in `react` and `togglePin` (aborting/rolling back optimistic state and showing an error on failure), and separate `notice` (success) state from `error` state.
