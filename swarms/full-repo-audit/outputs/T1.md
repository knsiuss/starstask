# T1 Audit Report: Web API, Auth, Security & Data Hygiene

Scope: `apps/web/src/app/api/**` (172 route files), `apps/web/src/lib/db/**`, `apps/web/src/lib/auth/**`, `apps/web/src/lib/security/**`.
Mode: Read-only audit.

---

## Findings

### [HIGH] Self-escalation of course access scope (`selected` -> `all`) by restricted members
- **File + Line:** `apps/web/src/app/api/classes/[slug]/members/me/courses/route.ts:15-18,58-92` and `apps/web/src/lib/db/course-access.ts:149-243`
- **Evidence:** `PUT /api/classes/[slug]/members/me/courses` only requires `requireClassMember(slug)` (line 68) and validates the body with `selfCourseAccessSchema` (`scope: z.enum(["all", "selected"])`, line 16). It then calls `setMemberCourseAccess({ classId: found.id, userId: session.user.id, scope: parsed.data.scope, subjectIds: parsed.data.subjectIds })`, which uses `createSupabaseAdminClient()` (`course-access.ts:155`) to update `class_members.course_scope`. A retake student whose `course_scope` was restricted to `"selected"` by a class manager via `PUT /api/classes/[slug]/members/courses` can call `/members/me/courses` with `{ "scope": "all" }` and bypass their course restriction.
- **Recommended Fix:** Enforce a server-side guard in `PUT /api/classes/[slug]/members/me/courses` (or `setMemberCourseAccess`) so non-managers cannot change `course_scope` from `"selected"` to `"all"` (or disallow `scope: "all"` on the self-service endpoint once restricted by a manager).

### [MEDIUM] PostgREST `.or()` filter injection via unsanitized search input in class lookup
- **File + Line:** `apps/web/src/app/api/classes/lookup/route.ts:16-21,78,100,119`
- **Evidence:** `POST /api/classes/lookup` creates `const admin = createSupabaseAdminClient()` (line 78) and interpolates user-controlled `code` / `term` directly into PostgREST `.or()` filter strings:
  - Line 100: `.or(\`class_code.ilike.${code},name.ilike.%${code}%\`)`
  - Line 119: `.or(\`slug.ilike.${term},class_code.ilike.${term},name.ilike.%${term}%\`)`
  `lookupSchema` allows `className: z.string().trim().min(2).max(120)` without stripping PostgREST filter metacharacters (`,`, `(`, `)`, `*`, `.`), allowing a caller to alter the `.or()` filter expression executed with the admin client.
- **Recommended Fix:** Strip or reject PostgREST filter metacharacters (`,`, `(`, `)`, `*`, `\`) before constructing `.or()` strings, or move the lookup into a parameterized Postgres RPC.

### [MEDIUM] Fail-open error handling in `filterRosterByCourseAccess`
- **File + Line:** `apps/web/src/lib/db/course-access.ts:59-97` (specifically lines 69, 94-96)
- **Evidence:** `filterRosterByCourseAccess` uses `createSupabaseAdminClient()` (line 69) to filter out `course_scope = 'selected'` members who are not enrolled in `subjectId`. Its `catch` block (lines 94-96) swallows all errors and returns the unfiltered `roster`, failing open and exposing non-enrolled students in attendance sheets/exports if the query fails.
- **Recommended Fix:** Throw `DataAccessError` (fail closed) on query failure instead of returning the unfiltered `roster`.

### [MEDIUM] Missing `enforceRateLimit` on 5 class/course mutation endpoints
- **File + Line:**
  - `apps/web/src/app/api/classes/[slug]/branding/route.ts:30-55` (`PUT`)
  - `apps/web/src/app/api/classes/[slug]/courses/[courseId]/comments/[commentId]/reactions/route.ts:16-62` (`POST`)
  - `apps/web/src/app/api/classes/[slug]/courses/[courseId]/comments/[commentId]/route.ts:11-44` (`DELETE`)
  - `apps/web/src/app/api/classes/[slug]/members/courses/route.ts:58-90` (`PUT`)
  - `apps/web/src/app/api/classes/[slug]/members/me/courses/route.ts:58-92` (`PUT`)
- **Evidence:** None of these 5 mutation handlers call `enforceRateLimit`. Notably, `reactions/route.ts` triggers `toggleCourseCommentReaction` (which runs up to 3 optimistic-concurrency retries via `createSupabaseAdminClient()`), and both `members/courses/route.ts` and `members/me/courses/route.ts` invoke `setMemberCourseAccess` via `createSupabaseAdminClient()`.
- **Recommended Fix:** Add `await enforceRateLimit({ action: ..., identifier: session.user.id, ... })` immediately after auth in each of these 5 handlers.

### [MEDIUM] Legacy DM routes lack route-level `getSessionUser()`, user-keyed rate limits, and Zod validation
- **File + Line:**
  - `apps/web/src/app/api/dm/conversations/route.ts:16-120` (`GET`, `POST` — `otherUserId` only checked with `typeof otherUserId !== "string" || !otherUserId`, no UUID check)
  - `apps/web/src/app/api/dm/conversations/[id]/messages/route.ts:21-125` (`GET`, `POST` — `id` not validated as UUID; `ciphertext` has no max length; `groupWraps` cast without validation; `attachment` validated ad-hoc)
  - `apps/web/src/app/api/dm/conversations/[id]/messages/[messageId]/route.ts:49-98` (`PATCH`, `DELETE` — no UUID validation on `id`/`messageId`; no Zod on `body`)
  - `apps/web/src/app/api/dm/conversations/[id]/messages/[messageId]/react/route.ts:12-49` (`POST` — `String(body?.emoji ?? "").slice(0, 8)` without Zod)
  - `apps/web/src/app/api/dm/conversations/[id]/block/route.ts:14-49` (`POST` — no UUID validation on `id`)
  - `apps/web/src/app/api/dm/conversations/[id]/prefs/route.ts:14-68` (`PATCH` — manual `typeof` checks without Zod)
  - `apps/web/src/app/api/dm/conversations/[id]/read/route.ts:12-37` (`POST` — no UUID validation on `id`)
  - `apps/web/src/app/api/dm/conversations/[id]/typing/route.ts:32-74` (`GET`, `POST` — no UUID validation on `id`)
  - `apps/web/src/app/api/dm/keys/me/route.ts:12-78` (`GET`, `PUT` — manual `typeof publicKey` check without Zod)
- **Evidence:** Unlike `dm/devices/route.ts` and `dm/conversations/[id]/sender-keys/route.ts`, these 9 routes do not call `getSessionUser()` at the route boundary (relying on downstream RLS/RPC `42501` errors), key `enforceRateLimit` on `getClientIdentifier(request)` (shared NAT IP) rather than `session.user.id`, and parse `params` and `request.json()` without Zod.
- **Recommended Fix:** Call `getSessionUser()` at the top of each handler, key `enforceRateLimit` on `session.user.id`, and validate all UUID params and JSON bodies with Zod schemas (matching `dm/devices/route.ts`).

### [LOW] `select("*")` on internal observability views in `plugins.ts`
- **File + Line:** `apps/web/src/lib/db/plugins.ts:170-180`
- **Evidence:** `getObservabilityViews()` runs `.select("*")` against `dual_write_drift`, `nim_drift`, and `observability_tenant_gap` using `adminClient()`. (Note: `apps/web/src/lib/db/direct-messages.ts:511` uses `.select("*", { count: "exact", head: true })`, which returns no row data.)
- **Recommended Fix:** Specify explicit column lists in `plugins.ts:173,177,179`.

### [LOW] Raw `error.message` forwarded in 3 route error responses
- **File + Line:**
  - `apps/web/src/app/api/profile/claim-lecturer/route.ts:69-70` (forwards Postgres `22023` `error.message` to `ApiError`)
  - `apps/web/src/app/api/classes/[slug]/courses/[courseId]/comments/route.ts:130-132` (forwards caught upload `error.message` to `ApiError`)
  - `apps/web/src/app/api/classes/[slug]/materials/upload/route.ts:52-54` (forwards caught upload `error.message` to `ApiError`)
- **Evidence:** Unexpected `Error` instances in these `catch` blocks expose their raw `error.message` in HTTP 422 JSON responses.
- **Recommended Fix:** Map known validation error types/codes to fixed user-facing messages and fall back to generic error strings for unknown errors.

## Verified Clean Areas

- **Cron endpoints (`apps/web/src/app/api/cron/**`):** All 9 cron routes enforce `isAuthorizedCronRequest(request)` (`timingSafeEqual` against `CRON_SECRET`, failing closed when unset).
- **Admin & Developer endpoints (`apps/web/src/app/api/admin/**`, `apps/web/src/app/api/developer/**`):** All 8 admin routes enforce `requirePlatformAdmin()` or `requireSession()` + `getClassRole()` (`canManage`) with rate limiting; all 5 developer routes enforce `requireDeveloperApiAccess()` with rate limiting.
- **Google OAuth & Redirects (`apps/web/src/app/api/integrations/google-*/**`, `apps/web/src/lib/security/redirect.ts`):** `safeRedirectPath` blocks open redirects; Google Calendar & Drive OAuth routes bind `httpOnly` + `SameSite=Lax` state cookies to `session.user.id` and redirect only to hardcoded settings/login paths.
- **QStash Worker (`apps/web/src/app/api/worker/export/route.ts`):** Verifies `upstash-signature` via `@upstash/qstash` `Receiver` before parsing or claiming jobs.
- **Error Handling & Logging (`apps/web/src/lib/api/responses.ts`):** `handleRouteError` returns generic 500 messages and logs only error `name` + digest. Zero `console.log` calls found in `apps/web/src/app/api/**` or `apps/web/src/lib/db/**`.
