# P4 Implementation Summary — Mobile Fixes & Prettier Cleanup

## 1. Mobile Fixes

### 1.1 Authenticated `POST` Disconnect in `Integrations.kt` & `SettingsScreens.kt`
- **Files:**
  - `apps/mobile/android/app/src/main/java/id/starstask/mobile/data/Integrations.kt`
  - `apps/mobile/android/app/src/main/java/id/starstask/mobile/ui/screens/SettingsScreens.kt`
- **Changes:**
  - Replaced `openIntegrationDisconnect(context, kind)` (which opened a `GET` browser `Intent` against `POST`-only endpoints) with `IntegrationDisconnectResult` (`Disconnected` / `Failed`) and `suspend fun disconnectIntegration(kind: IntegrationKind): IntegrationDisconnectResult`.
  - `disconnectIntegration` reads the current Supabase session access token (`SupabaseProvider.client.auth.currentSessionOrNull()?.accessToken`), validates `BuildConfig.SITE_URL`, and sends an authenticated `POST` request (`Authorization: Bearer <token>`, `Accept: application/json`) via `HttpURLConnection` on `Dispatchers.IO` to `kind.disconnectPath` (`/api/integrations/google-calendar/disconnect` and `/api/integrations/google-drive/disconnect`).
  - Updated the sole caller `SettingsHubScreen.disconnect(kind)` in `SettingsScreens.kt` to launch `disconnectIntegration(kind)` inside `rememberCoroutineScope()`, preventing concurrent disconnect calls via `disconnecting` state, refreshing status on success, and displaying user-friendly `notice` messages on success or failure.

### 1.2 `Calendar.kt` `data.eventId` Parsing
- **File:** `apps/mobile/android/app/src/main/java/id/starstask/mobile/data/Calendar.kt`
- **Changes:**
  - Updated `syncSessionToGoogleCalendar` to parse `root["data"]?.jsonObject?.get("eventId")?.jsonPrimitive?.contentOrNull` with fallback to `root["eventId"]?.jsonPrimitive?.contentOrNull`.
